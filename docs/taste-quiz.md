# Знакомство со вкусом через выбор образов

В веб-интерфейсе кнопка «Узнать мой стиль» открывает серию из шести
сравнений. Пользователь выбирает один образ или пропускает пару.
Можно закрыть окно раньше: уже принятые ответы сохраняются.
Повторное открытие начинает следующую короткую серию; просмотренные пары
не повторяются. Когда пары заканчиваются, интерфейс сообщает об этом.

## Подготовка карточек

Готовый каталог находится в `data/taste_cards.json`: 71 карточка из локальной
папки `outfit_cards`. Для всех изображений подготовлены русские описания
и признаки по результатам визуального просмотра. 12 побайтово одинаковых
копий удалены; похожие, но различные коллажи сохранены.

Запусти `uv run python main.py web` и открой `http://127.0.0.1:8000/cards`:
в галерее есть поиск, фильтр по стилю и просмотр изображения крупно с признаками.
Кнопка «Узнать мой стиль» открывает сравнение пар в основном интерфейсе.
Галерея предназначена для просмотра; описания редактируются в JSON.

Для новой карточки добавь изображение в `outfit_cards` и запись в каталог.
Путь к альтернативному каталогу можно задать переменной `CHERRY_TASTE_CARDS`.
Пример записи:

```json
{
  "id": "outfit_new_001",
  "image_path": "outfit_cards/my-outfit.jpg",
  "description": "Белая рубашка, широкие чёрные брюки и чёрные босоножки.",
  "attributes": ["color:white", "color:black", "fit:wide_leg", "item:shirt", "item:trousers"],
  "annotation_source": "manual"
}
```

Поля карточки:

- `id`: постоянный уникальный идентификатор. Для существенно изменённого образа используй новый ID.
- `image_path`: путь относительно корня проекта, внутри `outfit_cards`. Пробелы,
  скобки, символ `#` и отсутствие расширения поддерживаются; файлы переименовывать не нужно.
- `image_url`: альтернативный вариант для внешней HTTPS-ссылки. Указывай только
  одно из полей `image_path` и `image_url`.
- `description`: описание образа для галереи и альтернативного текста изображения.
- `attributes`: видимые признаки в формате `category:target`.
- `annotation_source`: `ai_visual_review` для текущей разметки или `manual` после ручной подготовки.

ID закреплён за карточкой: при добавлении файлов существующие ID не меняются.
Пропуски в нумерации остались после удаления копий. Картинки доступны через
`/api/taste/images/<id>`; произвольный путь к файлу через этот маршрут не принимается.

Категории: `color`, `silhouette`, `fit`, `material`, `pattern`, `detail`,
`item`, `style`. Значения — английские названия в snake_case, совпадающие
со словарём признаков товаров: например `fit:oversized`, `material:lace`.
Текущая разметка создана ИИ по видимым признакам. Стилевые обозначения —
интерпретация образа, которую можно уточнить вручную. Состав ткани, цена,
подлинность брендов и характеристики человека не определялись.
Косметика, телефоны, напитки и предметы оформления коллажей не включены
в признаки одежды. Новые файлы не размечаются автоматически при запуске.

Для наполнения коллекции стоит использовать несколько примеров одного
направления и образы, где цвет, посадка и детали комбинируются по-разному.
Иначе невозможно отличить интерес к цвету от интереса к силуэту.
Сопоставимые фон, размер изображения и подача помогут сделать сравнение понятнее.
Не добавляй характеристику материала, если она не известна по исходным данным.

## Как результаты влияют на рекомендации

История хранится в SQLite: `data/taste.sqlite3` или путь из `CHERRY_TASTE_DB`.
Каждый ответ содержит снимки обеих карточек; дальнейшее редактирование коллекции
не меняет смысл прошлых ответов. Данные привязаны к User ID и переживают
сброс чата и перезапуск сервера. В текущем демо User ID задаётся вручную,
авторизации нет; перед многопользовательским запуском его нужно брать из
аутентифицированной сессии. Явные предпочтения из чата по-прежнему используют
существующий InMemoryStore и не переживают перезапуск.

При загрузке Style DNA добавляются предпочтения с `source=pairwise`.
Явная запись о том же признаке имеет приоритет. Сигнал используется в
существующем поиске и ранжировании товаров. Проигравшая карточка не означает
жёсткого запрета: такие предпочтения исключены из `product_hard_conflicts`.

В первой версии используется осторожная эвристика:

1. Общие признаки пары не получают оценки.
2. Один голос распределяется между различающимися признаками; признаки
   победителя получают положительный вклад, второго образа — отрицательный.
3. Противоречивые ответы уменьшают итоговый сигнал; пропуски не меняют профиль.
4. `confidence = abs(сумма вкладов) / (сумма весов + 2)`, сила всегда `weak`.
   Это вес предварительного сигнала, а не статистически калиброванная вероятность.

Пары выбираются из ещё не показанных, с приоритетом менее просмотренных
карточек. Стороны и равнозначные варианты перемешиваются. Это стартовая
механика исследования коллекции; адаптивный выбор по неопределённости модели
и проверка качества на реальных пользователях остаются следующими шагами.

## API

- `POST /api/taste/session`, JSON `{"user_id": "alice"}`: предложение пройти тест или следующий шаг уже начатого теста.
- `POST /api/taste/answer`, JSON `{"user_id": "alice", "round_id": "...", "choice": "left"}`:
  сохранить ответ (`left`, `right`, `skip`).

Повтор такого же ответа идемпотентен. Изменение уже принятого ответа
отклоняется. API принимает только выданные данному пользователю пары.
